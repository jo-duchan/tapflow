# 최초 설정

새로운 릴레이에서 tapflow 대시보드를 처음 설정하는 과정을 안내합니다.

::: tip 릴레이가 먼저 실행 중이어야 합니다
릴레이 설정이 아직 안 되어 있다면 [릴레이 배포](/ko/guide/self-hosting)를 먼저 확인하세요.
:::

## 1. 관리자 계정 생성

tapflow는 기본 인증 정보가 없습니다. 최초 실행 시 대시보드가 설정 페이지로 자동 이동합니다.

1. 릴레이가 실행 중인 Mac의 브라우저에서 `http://localhost:4000`을 엽니다.
2. `/setup` 페이지로 자동으로 이동합니다.
3. 이메일과 비밀번호(최소 8자)를 입력합니다.
4. **Create admin account**를 클릭합니다.

첫 계정은 릴레이가 실행 중인 Mac에서만 만들 수 있습니다. 다른 기기에서 설정 페이지를 열면 폼이 나오지 않고 그 Mac에서 `tapflow admin init`을 실행하라는 안내가 나옵니다.

::: warning 최초 1회만 가능
설정 페이지는 계정이 하나도 없을 때만 표시됩니다. 이후 팀원 추가는 **Settings → Team**에서 초대로 진행합니다.
:::

::: tip 브라우저 없는 서버 환경이라면?
브라우저를 사용할 수 없는 경우 `tapflow admin init`으로 CLI에서 최초 관리자 계정을 생성할 수 있습니다. 릴레이가 먼저 구동 중이어야 합니다. 이 명령은 이메일과 비밀번호를 물어보기 때문에 터미널에서 직접 실행해야 하며 CI나 프로비저닝 스크립트에서는 실패합니다. 사람이 입력할 수 없는 설치라면 `TAPFLOW_ADMIN_EMAIL`과 `TAPFLOW_ADMIN_PASSWORD`를 설정해 릴레이가 시작하면서 계정을 만들게 하세요. 자세한 내용은 [설정](/ko/reference/configuration#create-the-first-admin-account-in-a-docker-container-tapflow-admin-email)을 참고하세요.
:::

## 2. 로그인

브라우저에서 `http://localhost:4000` (또는 릴레이 URL)으로 접속합니다. 방금 생성한 이메일과 비밀번호로 로그인합니다.

## 3. 팀원 초대

Admin으로 로그인한 뒤 **Settings → Team**에서 초대 링크를 만듭니다:

1. **Invite member**를 클릭합니다.
2. 팀원의 이메일과 역할을 선택합니다:
   - **Admin** — 자기 계정 삭제를 빼고 모든 작업을 할 수 있습니다. 팀원 초대·역할 변경·삭제, 비밀번호 재설정, 워크스페이스 설정, **Settings → Tokens** 페이지는 Admin만 사용할 수 있습니다.
   - **Developer**, **QA** — 앱 추가·수정·삭제, 빌드 업로드, 빌드 상태 변경, 빌드 삭제 예약, 웹훅 관리를 할 수 있습니다. 두 역할의 권한은 같습니다.
   - **Viewer** — 읽기 전용입니다. 빌드를 보고 QA 세션에서 시뮬레이터나 에뮬레이터로 테스트하고 댓글을 남길 수 있습니다. 빌드와 앱은 바꿀 수 없습니다. 웹훅은 조회도 변경도 할 수 없습니다.

   댓글 작성과 세션 시작은 역할과 관계없이 로그인한 팀원 누구나 할 수 있습니다. 역할을 바꾸면 역할을 확인하는 API에는 팀원이 다시 로그인하지 않아도 바로 적용됩니다.
3. **Generate invite link**를 클릭합니다. 초대 링크가 다이얼로그에 표시되며 브라우저가 허용하면 클립보드에도 복사됩니다. SMTP가 설정되어 있으면 팀원에게 비밀번호 설정 링크가 담긴 초대 이메일도 발송됩니다.

::: tip SMTP 설정 전인 경우
SMTP가 설정되지 않았다면 초대 다이얼로그에 표시된 링크를 복사해 직접 공유하세요. SMTP 설정 방법은 [설정 파일](/ko/reference/configuration)을 참고하세요.
:::

## 4. 첫 번째 앱 추가

**App Center**로 이동합니다. 앱을 추가하는 두 가지 방법이 있습니다:

**방법 A — 빌드 업로드**: **Upload build**를 클릭하고 파일을 선택합니다. tapflow가 bundle ID, 버전, 빌드 번호를 자동으로 읽어 App 항목을 생성합니다.

- iOS: `.app.zip` 또는 `.tar.gz`/`.tgz` 시뮬레이터 빌드
- Android: `.apk`

**방법 B — 앱 수동 생성**: 사이드바에서 **+ Add App**을 클릭하고 앱 이름, bundle ID, 플랫폼을 입력합니다. 빌드가 준비되기 전에 앱을 먼저 등록할 때 사용합니다.

동일한 bundle ID의 다른 플랫폼 App이 이미 있으면 하나의 App으로 통합됩니다 (`both`).

## 5. 세션 시작

App Center에서 빌드 행을 클릭하면 QA 세션 화면이 열립니다. **Select Mac**에서 Mac을 고르고 **Select device**에서 기기를 클릭하면 세션이 시작됩니다. 기기 화면이 실시간으로 브라우저에 스트리밍됩니다.

## 6. 팀원에게 공유하기

이제 팀원이 직접 테스트할 수 있도록 접속 정보를 전달합니다. 팀원은 tapflow를 설치할 필요가 없습니다. 브라우저만 있으면 됩니다.

**접속 URL 전달.** 공유할 URL은 배포 방식에 따라 다릅니다 (`localhost`는 릴레이 Mac 본인 전용이라 공유할 수 없습니다).

| 배포 방식 | 팀원이 접속할 주소 |
|-----------|-------------------|
| 같은 사무실 네트워크 | 릴레이 Mac의 LAN IP, 예: `http://192.168.0.10:4000` |
| Tailscale 터널 | 시작 배너에 출력된 tailnet URL (팀원도 Tailscale 설치 필요) |
| VPS + rathole 터널 | 시작 배너에 출력된 공개 URL, 예: `https://your-vps.com` |

배포 방식별 자세한 내용은 [릴레이 배포](/ko/guide/self-hosting)를 참고하세요. 팀원이 어느 경로로 접속하느냐에 따라 받는 스트림 품질도 달라집니다. 같은 LAN이라도 평문 HTTP면 **Standard**, HTTPS면 더 부드러운 **Smooth** 프로파일이 적용됩니다. 접속 환경별 프로파일은 [스트림 품질](/ko/guide/streaming)을 참고하세요.

**초대 수락.** [3단계](#_3-팀원-초대)에서 보낸 초대를 팀원이 수락하면 비밀번호를 설정하고 바로 로그인합니다. SMTP가 설정되지 않았다면 초대 링크를 직접 전달하세요.

**팀원이 하는 일.** 로그인한 팀원은 별도 도구 설치 없이 바로 테스트할 수 있습니다.

1. App Center에서 빌드를 선택합니다.
2. Mac과 기기를 골라 세션을 시작합니다.
3. 브라우저에서 시뮬레이터·에뮬레이터를 직접 조작하고, 빌드별 댓글로 피드백을 남깁니다.

팀원이 할 수 있는 작업은 초대 시 부여한 역할(Admin / Developer / QA / Viewer)에 따라 다릅니다. 역할별 권한은 위 [3. 팀원 초대](#_3-팀원-초대)를 참고하세요.
