# AI 에이전트 QA {#ai-agent-qa}

AI 에이전트 QA는 Claude Code 같은 AI 에이전트가 tapflow의 기기를 조작해 앱을 테스트하는 방식입니다. AI 에이전트는 [MCP 서버](/ko/ai-agents/mcp-server)로 화면을 읽고 탭과 텍스트 입력을 보냅니다. 이 기기는 팀원이 QA 세션에서 사용하는 것과 같은 시뮬레이터와 에뮬레이터입니다.

## AI 에이전트 연결 {#connect}

AI 에이전트를 쓰는 사람은 npm으로 MCP 서버를 설치하고 AI 에이전트의 MCP 설정에 서버를 등록합니다. 이때 릴레이 주소와 대시보드에서 발급한 API 유형 개인 액세스 토큰(PAT)도 함께 등록합니다. 릴레이와 에이전트는 평소처럼 계속 실행되므로 운영자가 추가로 설정할 항목은 없습니다. 설정 순서는 [MCP 서버](/ko/ai-agents/mcp-server)를 참고하세요.

## 테스트하고 플로우 저장 {#test-and-save}

연결을 마치면 AI 에이전트에 “로그인 화면을 테스트해 줘”와 같이 요청할 수 있습니다. AI 에이전트는 기기를 선택하고 앱을 설치한 다음 화면을 읽으며 테스트할 수 있습니다. AI 에이전트는 기기 화면으로 연결되는 링크도 제공합니다. 대시보드에 로그인한 사람은 누구나 링크를 열어 화면을 실시간으로 볼 수 있지만 링크에서 기기를 조작할 수는 없습니다.

AI 에이전트는 [AI 에이전트 Flow Capture](/ko/ai-agents/agent-flow-capture)로 확인한 경로를 플로우 YAML로 저장할 수 있습니다. tapflow는 기기를 초기화하고 플로우를 재생합니다. 재생을 통과한 경우에만 플로우를 반환합니다. 재생에는 AI 모델을 사용하지 않습니다.

## CI에서 실행 {#ci}

저장한 플로우는 AI 모델 없이 CI에서 재생할 수 있습니다. [자동화 QA](/ko/automation)의 [CI에서 플로우 실행](/ko/automation/ci)을 참고하세요.

아직 플로우로 저장하지 않은 시나리오도 CI에서 실행할 수 있습니다. 이 경우 AI 에이전트가 실행할 때마다 화면을 판단합니다. 실행할 때마다 결과가 달라질 수 있으며 API 호출 비용이 발생합니다. 자세한 내용은 [CI에서 탐색적 실행](/ko/ai-agents/exploratory-runs)을 참고하세요.

## 관련 문서 {#related}

- [MCP 서버](/ko/ai-agents/mcp-server)는 설치와 AI 에이전트 등록 방법, 제공하는 도구, 기기 화면을 지켜보는 방법을 설명합니다.
- [자동화 QA](/ko/automation)는 플로우를 만드는 방법과 재생 및 실행 기록을 설명합니다.
- [수동 QA](/ko/testing)는 팀원이 브라우저에서 직접 빌드를 테스트하는 방법을 설명합니다.
